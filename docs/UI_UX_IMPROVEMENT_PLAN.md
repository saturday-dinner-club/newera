# 테마와 UX 개선 계획

상태: **구현 및 검증 완료 — 결과와 범위는 10절 참고**

작성일: 2026-11-01 KST
대상: 공연 화면(`/`), 작업실(`/lores`), 이미지 프리셋(`/images`)

사용자 확정 사항은 **다크·라이트 테마 모두 지원**이다. 아래 색상·수치·화면 구성은 구현과 시안 검증을 위한 제안이다. 현재 동작의 기준은 [PRODUCT](PRODUCT.md)와 실행 코드이며, 이 문서는 이후 UI 작업의 범위·순서·완료 조건을 관리한다. 기존의 행동·대사 조각 출력 변경을 포함한 현재 작업 트리를 분석 기준으로 삼았다.

## 1. 제품 경험의 방향

**읽기 → 내 행동과 대사 입력 → 인물의 반응 관찰 → 다시 읽기**가 끊기지 않는 이야기 도구를 목표로 한다.

- 극장이라는 정체성은 절제된 조명색, 화자 표기, 지문과 대사의 리듬으로 표현한다.
- 공연은 이야기 본문과 다음 입력을 중심으로 구성한다. 세계관 관리·저장 슬롯·모델·기억 검사는 필요할 때 연다.
- 작업실은 찾기·수정·저장·공연 확인이 연결되는 제작 도구로 구성한다.
- 같은 버튼·입력·탭·상태 표시는 세 화면에서 같은 의미와 모양을 가진다.
- 테마·독서 설정은 사용자 환경 설정이다. 세계관 설정·게임 진행·저장 슬롯과 분리한다.

## 2. 확인한 사실과 개선 제안

2026-11-01 ego-browser로 격리된 로컬 데이터에서 점검했다. 데스크톱 1440×1000, 모바일 크기 390×844·360×640, 짧은 화면 390×500을 사용했다. 390×500 검사는 작은 뷰포트 검사이며 실제 모바일 키보드 동작을 검증한 것은 아니다.

| 확인한 사실 | 사용자에게 미치는 영향 | 제안 / 우선순위 |
| --- | --- | --- |
| 입력창 위의 답변 대기 문구가 `.player-console > .eyebrow { display: none; }`으로 숨겨짐 | 과거 기록을 읽으면 남은 시간과 내 입력 차례를 놓침 | 입력창에 고정된 상태 표시 / 최우선 |
| 360×640에서 대화 영역 약 97px, 390×500에서 약 18px | 여러 행동·대사를 이어 읽기 어려움 | 짧은 화면용 헤더·입력창 구성 / 최우선 |
| 세계관 이름을 수정한 뒤 씬 탭으로 갔다 돌아오면 미저장 값이 사라짐 | 작성 내용 손실 | 탭별 초안 유지 및 이동 보호 / 최우선 |
| 입력 안내 문구의 실제 글자 크기 약 9.17px | `*행동*`과 `"대사"` 규칙을 읽기 어려움 | 명시적인 보조 글자 크기와 예시 도움말 / 높음 |
| 대기 중 ‘잠시 지켜본다’와 이동 버튼은 비활성화되고, 별도의 즉시 진행 버튼은 없음 | 답할 내용이 없는 경우 대기 시간을 모두 기다리게 됨 | ‘지금 이어가기’ 제공 / 높음 |
| 공연은 작은 각진 컨트롤, 작업실은 큰 둥근 카드, 이미지 화면은 별도 색상·간격을 사용 | 화면 간 전환 시 하나의 제품이라는 인상이 약함 | 공통 테마 토큰과 컴포넌트 규칙 / 높음 |

태그를 눌러 대상을 선택하고 입력하는 동작, 행동·대사 6개를 순서대로 표시하는 동작은 확인했다. 이미지 생성 서버 미연결 안내는 점검 환경에 따른 상태이며 UI 결함으로 분류하지 않는다. 실제 모델·이미지 생성 품질은 이번 분석에 포함하지 않았다.

## 3. 다크·라이트 테마

### 공통 구조

- 같은 레이아웃·글자·아이콘·컨트롤을 사용하고 의미별 색상 토큰을 교체한다.
- 테마 선택은 ‘시스템 / 다크 / 라이트’로 제공한다. 기본값은 시스템을 따르는 안을 제안한다.
- 명시적으로 고른 설정은 브라우저에 보존하고 세 화면과 세계관 전환에 공통 적용한다.
- 첫 화면을 그리기 전에 테마를 해석해 밝거나 어두운 화면이 순간적으로 번쩍이는 현상을 막는다.
- 시스템 모드에서만 운영체제 테마 변경을 따라간다.
- 모달·드롭다운·입력창·브라우저 기본 컨트롤·오류·비활성 상태까지 두 테마로 확인한다.

### 시각 방향과 토큰 초안

다크는 조용한 객석, 라이트는 밝은 대본의 인상을 사용한다. 본문 주변 장식을 줄이고, 따뜻한 금빛은 브랜드와 선택 상태에 제한해서 사용한다.

| 역할 | 다크 초안 | 라이트 초안 |
| --- | --- | --- |
| 화면 배경 | 짙은 중성 차콜 | 은은한 밝은 중성색 |
| 본문·입력 표면 | 배경보다 조금 밝은 차콜 | 밝은 종이색 |
| 보조 패널·모달 | 한 단계 올라온 표면 | 본문과 구분되는 밝은 표면 |
| 기본 글자 | 부드러운 밝은 회백색 | 짙은 먹색 |
| 보조 글자 | 읽을 수 있는 회색 | 기본 글자보다 약한 진회색 |
| 선택·주요 동작 | 밝은 앰버 | 명암 차이가 충분한 짙은 앰버 |
| 성공·오류·대기 | 의미별 색상 + 문구 | 같은 의미를 가진 테마별 색상 + 문구 |

구현 시 `page`, `surface`, `surface-raised`, `text`, `text-muted`, `border`, `accent`, `focus`, `success`, `warning`, `danger` 역할을 공통 CSS 변수로 정의한다. 화면별 직접 색상 지정은 이 역할로 정리한다. 확정 색상은 두 테마의 실제 시안과 브라우저 명암 검토 후 정한다.

### 글자와 조작 요소

- 이야기 본문은 17~18px, 줄 높이 약 1.8을 시작점으로 삼고 읽기 크기 설정을 제공한다.
- UI 본문·컨트롤은 14~16px, 보조 안내는 최소 12px를 기본으로 검토한다.
- 긴 본문의 폭은 현재의 읽기 폭 제한을 유지하면서 대략 60~72자 수준으로 조정한다.
- 모바일 주요 조작 요소의 터치 영역은 44px 안팎을 목표로 한다.
- 일반 버튼·위험 버튼·보조 버튼·태그·탭의 모양과 선택/호버/포커스/비활성 상태를 공통화한다.
- 색상 외에도 글자·테두리·선택 표식을 사용한다. 화자마다 무작위 색을 추가하지 않는다.

## 4. 공연 화면 UX

### 기본 배치

```text
현재 장소 · 이야기 시간                         메뉴

                 대화 기록
          행동·대사 조각을 순서대로 표시

답변을 기다립니다 04:32                지금 이어가기
모두에게   서연   하린 …
나의 행동과 대사                                 보내기
```

상태 줄은 필요한 상태에서 표시한다. 기록을 위로 스크롤해도 입력과 현재 진행 상태는 확인할 수 있어야 한다.

### 화면 크기별 구성

- 넓은 화면은 기록을 중심에 두고 세계관·현장 정보 패널의 열고 닫기를 지원한다.
- 모바일은 한 개의 간결한 헤더를 사용한다. 모델·저장 슬롯·초기화 등 빈도가 낮은 기능은 메뉴로 옮긴다.
- 주변 사물·인물 정보·기억은 보조 패널로 연다. 닫힌 상태에서 본문 높이를 크게 차지하지 않게 한다.
- 현장 인물 **7명까지 태그, 8명부터 드롭다운** 규칙은 유지한다. 모바일 태그는 한 줄 가로 스크롤로 높이를 제한한다.
- 짧은 화면에서는 위치 안내와 입력 보조 문구를 압축하고, 입력창은 작은 높이에서 시작해 작성량에 따라 늘어난다.
- 입력 도움말은 접어서 볼 수 있는 예시로 제공한다. 행동·대사 문법 자체는 유지한다.
- ‘새 내용’ 표시와 최신 기록으로 돌아가기 조작을 제공한다. 이전 기록을 읽는 동안에는 위치를 유지한다.
- 삽화는 기록 안에서 읽기 흐름에 맞게 표시하고 접을 수 있게 한다. 삽화 로딩으로 읽던 위치가 튀지 않아야 한다.

### 상태별 조작

| 상태 | 표시 | 사용할 수 있는 주요 조작 |
| --- | --- | --- |
| 입력 가능 | 다음 말이나 행동을 입력하세요 | 대상 선택, 입력, 이동, 사물 상호작용 |
| 입력 전송 중 | 입력을 보내고 있습니다 | 중복 전송 방지, 작성 내용 보존 |
| 인물 반응 생성 중 | 인물들이 반응하고 있습니다 | 새 입력으로 개입, 생성 중단 |
| 답변 대기 | 내가 답할 차례, `분:초` 타이머 | 입력, 지금 이어가기 |
| 사용자 중단 | 자동 진행을 중단했습니다 | 새 입력, 이어서 진행 |
| 생성 실패 | 확정된 진행 범위와 실패 요약 | 재시도, 필요 시 모델 설정 |

사용자 중단과 생성 실패를 화면에서 구별한다. 필요한 경우 서버에서 구조화된 중단 사유를 제공하며, 오류 문장 자체를 분석해 상태를 추측하지 않는다. 이미 확정된 기록과 작성 중 초안의 보존 계약을 유지한다.

### ‘지금 이어가기’의 실행 계약

이 기능은 서버 작업과 연결해야 한다. 화면의 숫자만 줄이는 구현으로 끝내지 않는다.

- 현재 세계관·작업·답변 대기 대상에 연결된 진행 요청을 저장한다.
- 실행기는 현재 대기와 일치하는 요청만 소비해 대기를 끝낸다. 이전 질문에 대한 요청이 다음 질문을 건너뛰지 않아야 한다.
- 이미 도착한 플레이어 입력을 먼저 반영한다.
- 별도의 대사·행동 사건이나 게임 내 시간 진행을 만들지 않는다.
- 새로고침·서버 재시작과 입력/건너뛰기/시간 만료의 경합에서도 중복 실행하지 않는다.
- 일반적인 생성 중단과 동일한 실패 경로로 처리하지 않는다.

## 5. 작업실 UX

- 탭·세계관·편집 대상별로 초안을 유지한다. 현재 진행과 이야기 시작 시점의 초안도 구분한다.
- 저장하지 않은 내용이 있으면 표시하고, 초안을 버리는 이동에는 확인 또는 복원 수단을 제공한다.
- 새로고침 후 복원할 초안은 해당 세계관·대상·기준 리비전과 연결한다. 서버 내용이 바뀌었으면 자동으로 덮어쓰지 않고 복원 여부를 알린다.
- 저장과 취소는 현재 편집 중인 항목을 명시한다. 한 항목을 저장하면서 다른 초안까지 지워지지 않아야 한다.
- 장문의 세계관·인물 편집에는 저장 상태와 조작을 찾기 쉽게 유지한다.
- 장소와 인물은 이름 검색·종류·현재 위치로 찾을 수 있는 목록을 정리하고, 세부 편집을 연다.
- 씬 지도는 연결을 이해하는 도구로 유지하며 작은 화면에서는 접을 수 있게 한다.
- ‘지금의 모습 / 이야기 시작 시점’ 구분과 관계의 방향성은 읽기 쉬운 설명과 함께 유지한다.
- 저장 성공, 입력 검증 오류, 다른 변경과의 충돌을 서로 구별한다.

Provider의 인증 정보는 이야기 편집 초안 저장의 대상에 포함하지 않는다.

## 6. 모델·이미지 설정 UX

- 공연에서 자주 필요한 조작은 현재 모델·이미지 프리셋 선택이다. Provider 주소·인증·세부 생성 옵션은 설정 안에서 단계적으로 연다.
- 설정 화면의 순서는 현재 선택 확인 → Provider 연결 확인 → 모델/프리셋 선택 → 옵션 조정 → 저장 및 시험 사용으로 정리한다.
- 연결되지 않았거나 처음 설정하는 상태에서는 다음에 할 일을 설명한다. 동작 중 발생한 오류와 처음 방문한 미설정 상태를 구별한다.
- 이미지 프리셋 선택, 프리셋 편집, 한 번 생성하기의 관계를 구분해 보여준다.
- 저장된 프리셋을 전환할 때도 미저장 변경 보호를 적용한다.
- 실제 모델 호출·이미지 생성 검증에는 수동 실행과 공연 후 자동 삽화 조건이 충족되는 흐름을 모두 포함한다. 서버 접근 실패를 UI 전체 장애로 표시하지 않는다.

## 7. 구현 순서와 완료 조건

| 순서 | 작업 묶음 | 주요 대상 | 완료 조건 |
| --- | --- | --- | --- |
| 1 | 사용자 흐름 보호 | 공연 상태 표시, 작업실 초안 | 타이머를 항상 확인할 수 있고 탭 이동으로 초안이 사라지지 않음 |
| 2 | 다크·라이트 기반 | 테마 토큰, 공통 컨트롤, 설정 저장 | 세 화면의 두 테마 전환·새로고침·시스템 설정 추종이 일관되고 첫 화면 번쩍임이 없음 |
| 3 | 공연 레이아웃과 입력 개선 | 헤더, 기록, 상태 줄, 대상 선택, 입력창, 보조 패널 | 작은 화면에서도 기록을 읽고 입력할 수 있으며 7/8명 전환 규칙과 초안이 유지됨 |
| 4 | 대기·실패·복구 조작 | 서버 작업 제어와 공연 상태 UI | 즉시 이어가기와 입력 경합이 안전하고 중단/실패의 의미가 분명함 |
| 5 | 작업실과 설정 동선 정리 | 목록·검색·편집·저장, Provider와 이미지 프리셋 | 다음 조작과 저장 범위를 알 수 있고 항목 전환 시 작성 내용이 보호됨 |

각 묶음은 구현 후 바로 ego-browser에서 확인한다. 전체 UI를 한 번에 교체한 뒤 마지막에만 검증하지 않는다. 우선적인 상태 표시·초안 보호는 시각 시안을 만드는 동안에도 작은 수정으로 검증할 수 있다.

시각 구현 전에는 다크/라이트의 공연 화면과 모바일 답변 대기 화면, 작업실의 편집 상태를 시안으로 비교한다. 기존 `design/` 이미지는 과거 참고 자료이며 현재 기능에 대한 확정 시안으로 간주하지 않는다. 실제 구현은 현재 SvelteKit·Svelte 구조를 사용한다.

## 8. 검증 계획과 제안 목표

### 화면과 접근성

- 두 테마에서 1440×1000, 768×1024, 390×844, 360×640, 390×500을 확인한다.
- 기본 읽기 설정·보조 패널 닫힘 기준으로 360×640의 기록 영역 **240px 이상**, 390×500에서는 **160px 이상**을 목표로 한다. 현재 관측값이 아니라 재설계의 검증 목표다.
- 글자 확대, 긴 인물 이름, 현장 인물 0/1/7/8명, 6개 조각 출력, 긴 대화·삽화를 사용한다.
- 문서 전체의 가로 넘침, 겹친 컨트롤, 보이지 않는 주요 조작, 포커스 이동·포커스 표시를 확인한다.
- 타이머는 계속 보이되 스크린리더가 매초 숫자를 반복해서 읽지 않게 한다.
- 실제 모바일 키보드·확대·안전 영역은 지원 환경에서 별도로 확인한다. 뷰포트 축소 검사만으로 검증 완료라고 하지 않는다.

### 동작과 상태

- 테마를 바꿔도 진행·초안·선택 대상·읽던 위치가 유지된다.
- 대기 중 실제 입력, 건너뛰기, 시간 만료가 겹쳐도 입력과 행동을 중복 반영하지 않는다.
- 응답 생성·오류·중단·재시도·새로고침 후에도 확정된 6개 조각의 순서와 이미 저장한 진행을 유지한다.
- 작업실에서 탭 이동·항목 변경·페이지 이동·새로고침을 하면서 초안 보호와 저장 성공/실패를 확인한다.
- 테마·레이아웃은 실제 ego 화면으로, 작업 제어와 저장 계약은 집중 단위/통합 테스트로 검증한다. 기존 `npm run check`, `npm test`, `npm run test:integration` 중 변경 범위에 해당하는 검사를 실행한다.

## 9. 다음 계획 갱신 시점

## 10. 2026-11-01 구현 결과

- 공연·작업실·삽화에 공통 의미 기반 색상 토큰과 시스템/다크/라이트 설정을 적용했다. 읽기 크기는 16/18/20px이며 테마와 함께 브라우저에 보관한다. 첫 화면에서 저장된 설정을 적용한다.
- 공연 입력창 위에 상태와 분:초 타이머를 고정하고 현재 질문만 건너뛰는 서버 제어를 연결했다. 입력을 우선하며 질문 ID와 기한이 다른 오래된 제어 요청은 무시한다. 사용자 중단은 구조화된 사유로 일반 실패와 구별한다.
- 모바일은 세계관·슬롯과 주변 사물을 별도 창으로 연다. 포커스를 창 안에 유지하고 Escape로 닫아 이전 조작으로 돌아간다. 대상 태그는 가로 스크롤하며 8명부터 드롭다운을 유지했다. 도움말과 이동은 접는다.
- 작업실은 방문한 탭·현재/초기 시점·관계 상대의 편집기를 유지한다. 검색으로 숨겨도 초안이 남고 한 항목 저장이 다른 초안을 초기화하지 않는다. 미저장 개수와 이동/새로고침 확인을 제공한다. **초안은 메모리에 유지하며 브라우저 저장소에 자동 저장하지 않는다.** 새로고침 후 복원은 이번 구현에 포함하지 않으며 이동 전 저장으로 보호한다. Provider 인증 정보도 초안으로 저장하지 않는다.
- 작업실의 목록 검색과 지도 접기, 모바일 세계관 관리 접기를 추가했다. 삽화 프리셋에는 미저장 표시와 전환/이동 보호를 추가했다.
- 이야기 화면의 판단·프롬프트·생성 단계 표시는 이야기 흐름에 맞는 안내로 대체하고 기술 기록과 상세 오류는 접힌 상세에 둔다.

검증: 단위 테스트 196개, 통합 테스트 22개, Svelte/TypeScript 검사 및 프로덕션 빌드. ego에서 두 테마의 1440×1000, 768×1024, 390×844, 360×640, 390×500 화면을 검사했다. 기본 보조 패널 닫힘 상태의 기록 영역은 360×640에서 366px, 390×500에서 226px이었다. 두 테마 모두 가로 넘침과 브라우저 런타임 오류가 없었다. 타이머의 스크롤 독립 표시, 창 포커스/닫기, 테마 저장/시스템 추종, 탭 전환 초안 유지와 개별 저장을 실제 UI로 확인했다. 실제 모바일 소프트 키보드·OS 확대와 실제 이미지 서비스 실행은 별도 확인 대상이다.
